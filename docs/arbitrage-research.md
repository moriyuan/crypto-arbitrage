# Bybit 与 Bitget 跨所永续套利研究进度和后续方向

更新日期：2026年10月14日，北京时间。最新实验于2026年10月13日完成。

当前保留 BTWUSDT 的双腿对手一档理想吃单回放基准。新增日内波动率过滤已关闭，价差持续时间不作为入场条件；六个盘口和成交速率候选均未达到晋级要求。下一步优先研究入场立即清算成本与止损预算的兼容性，再研究具有方向信息的盘口变化和主动成交压力。

本仓库是从原研究工作区提取的独立项目，研究 Bybit 与 Bitget 的虚拟币 USDT 永续合约跨所套利，不包含原 Binance BTC 分钟级 CTA 主项目。本页固定研究状态，不代表启用真实交易或启动下一轮实验。

## 当前基准交易逻辑

当前参数对应 `entry30 / tp20 / relative_sl10 / hard100 / hold15s`，来自此前冻结的理想吃单参数研究。以下数值为回放参数，不是已验证的实盘参数。

|项目|固定值与含义|
|---|---|
|本金|每个日期、每个参数情景独立开始；每所1000 USDT|
|手续费|每笔成交0.03%，即3bp；完整组合两开两平共4笔，费用按各笔实际名义金额计算|
|方向|在较便宜交易所买入 ask1，在另一所卖出 bid1；两腿 BTW 数量相同|
|入场原始价差|`20000 × (卖出所 bid1 − 买入所 ask1) / (卖出所 bid1 + 买入所 ask1)`，至少30bp；这不是已扣往返成本的净收益|
|仓位|每腿最多250 USDT、1倍；同时受两腿相关一档显示数量及现金含费用约束；按10 BTW步长向下取整，每腿开仓至少5 USDT|
|并发与冷却|最多一对持仓，全部平仓后冷却30秒；同一行情时点平仓后不重新开仓|
|活动门槛|两所过去60秒成交笔数和成交额分别达到各自 q25，最近成交距当前不超过5秒；仅限制新开仓|
|q25校准与交易时段|各日00:00–12:00 UTC历史数据校准，12:00 UTC后才开仓，23:58 UTC停止新增并触发日终退出请求；北京时间为当日20:00至次日07:58|
|止盈|扣开平四笔费用后的组合净清算收益达到单腿开仓名义金额的20bp|
|普通止损|相对入场当刻立即反向平仓净值，恶化达到单腿开仓名义金额的10bp；不是绝对净亏10bp|
|硬止损|组合净清算亏损达到单腿开仓名义金额的100bp|
|持仓期限|15秒为请求退出阈值；无有效盘口时等待，实际持仓可超过15秒，未保证超时上限|
|日亏停止|两所合计已实现亏损达到10 USDT后停止新增；触发前最后一组损失可能使最终亏损超过10 USDT|
|资金费护栏|依据当前已知结算公告；未知、过期，或距结算不超过持仓上限加60秒时，停止新增并请求退出|
|退出优先级|日终 → 资金费护栏 → 持仓超时 → 硬止损 → 普通止损 → 止盈|

为避免止损口径混淆，记 `N0 = BTW数量 × 多头开仓价格`，`P(t)`为当前两腿按反向一档平仓、扣四笔手续费后的净损益，`P0`为开仓时立即按反向一档平仓的净损益。三项条件分别是：

- 止盈：`P(t) / N0 × 10000 >= 20`。
- 普通止损：`(P(t) − P0) / N0 × 10000 <= −10`。
- 硬止损：`P(t) / N0 × 10000 <= −100`。

费用和四笔名义金额并不完全相同，因此不能用固定12bp代替实际费用记账。旧的“净±2bp”“毛±2bp”等设置不再是当前基准。

理想平仓允许全量按对手一档成交，即使退出量超过显示深度；历史盘口不会因模拟交易扣除数量。无有效盘口时不能凭空成交。当前回撤按有效行情下的理想清算净值计算，无效行情期间的未完成估值未计入，不能理解为完整风险上界。实现与口径见[基准引擎说明](../research/arb-runs/20261013-btw-perfect-taker-code/README.md)。

### 最新速率过滤结果

每所的速率比为 `12 × N5 / N60`，两所分别满足要求。book 的 N 是已接受的原始 L2 增量消息内买卖价位行数，含数量归零行、排除快照；trade 的 N 是已接受的实时成交笔数，排除 Bitget 首包历史成交。快照、断线和恢复按各自事件源处理，至少有60秒预热且分母大于0才可计算。

L2是聚合价位数据，不含逐订单ID，不能把更新行数当成新委托数或撤单数。各所滚动归一化也不能完全消除频道发布与聚合方式的差异。

|原基准|−10.0001|+0.0723|+2.6342|
|盘口速率至少1倍|−10.1250|+0.2575|−0.2011|

原基准三个日期分别完成80、17、80个组合，净盈利组合分别为4、8、34；净盈利次数不等于止盈触发次数。单日本金和账户路径独立，不能把各候选相加当成一个组合账户的收益。

候选晋级要求每个拟合日至少10个闭合组合、资金费和账务核验通过、无残仓，同时改善最差日净收益、两日合计净收益，并优于相应“仅检查特征可用性”的覆盖对照。六个候选均未通过。三类覆盖对照在这些日期复现了基准订单、组合和权益，但这不排除缺数影响过滤后新产生的其他入场路径。

### 盈亏原因和待解决问题

1. **回归不等于扣费后盈利。** 8月1日基准中价基差收敛收益1.6092 USDT，开平盘口成本7.3291 USDT，四笔费用4.2802 USDT，最终净亏10.0001 USDT。45组中价基差出现收敛，其中41组仍净亏。中价只用于事后归因，成交仍取对手一档。
2. **强度没有稳定区分方向。** 成交速率1倍在10月1日以47组获得2.3951 USDT，少于基准80组但保留大部分利润；其8月1日、9月1日却更差。盘口速率1倍在9月1日改善，10月1日毛收益1.5527 USDT不足以支付1.7538 USDT手续费，转为净亏。
3. **存在开仓成本和硬止损冲突。** 8月1日成交速率2倍组的第85个组合，开平发生在同一纳秒；入场立即清算净值为−126.785bp，已超过100bp硬止损，净亏1.797350214 USDT。该笔来自反向一档价差与费用，不能归因于网络延迟或等待回归。当前冻结引擎记录了此问题，但尚未添加开仓前成本限制。
4. **过滤改变后续交易路径。** 10月1日盘口速率1倍挡住原基准24个盈利、28个亏损入场，同时新增14个不同入场。不能只把原来被挡住的亏损相加，宣称新策略节省了这些损失。

## 下一步研究顺序

以下是后续工作计划，尚未实施或选择新的数值门槛。本次保存文档不自动启动回放。

|顺序|研究问题与拟增加参数|验证方式和接受条件|
|---|---|---|
|1 入场清算成本|先检查入场即清算是否已触硬止损；再研究 `max_entry_liquidation_cost_bps`。成本定义为 `max(0, −P0/N0 × 10000)`，包含反向盘口成本和四笔费用|先单独验证成本与硬止损预算兼容的条件；更严格成本上限另作少量固定候选。保持活动、报价和退出参数不变，核对是否确实减少成本型亏损，同时统计错失盈利与新增交易|
|2 方向性盘口变化|研究按套利方向调整的 L1 订单流失衡 OFI、买卖一数量增减、所内价差扩大或收窄；不能把聚合数量减少一律叫撤单|只使用决策前已收到的事件，处理换价、重置及缺口；先单指标，再考虑组合。统计单位名义净收益、成本和止损频次，不要求跨所价差持续|
|3 主动成交压力|研究便宜所主动买入、昂贵所主动卖出是否支持跨所基差收敛；候选包括按方向调整的买卖成交额失衡、成交强度与盘口更新强度的关系|先核对成交方向语义；冻结窗口和门槛后比较同一基准。检验方向性是否比单纯“发生得更快”更有区分力|
|4 新日期验证|增加未用于调参的交易日，先固定规则再查看结果；随后再考虑更多两所共同虚拟币合约|保留按时间分开的拟合与评估，不能利用评估日回改参数。全币种筛选与BTW单币种实验分开，历史准入不得引入已停用的波动率门槛|
|5 撮合约束验证|对有稳定改善迹象的候选，加入网络和执行延迟、部分成交、退出深度约束、单腿风险|与当前理想基准并列报告收益下降及风险，不把理想全额成交的利润直接当成可实现收益|

计划1与计划2应分开做消融，避免同时改变成本、信号、退出和仓位后无法解释改善来源。AS报价、现货辅助定价和价差持续门槛不在当前优先计划内；尤其价差持续时间不应以其他名字重新引入。

## 后续每轮回放的交付要求

- 回放前固定数据范围、参数候选、费用、撮合假设、拟合与评估日期、最低交易样本数和晋级标准；新建结果目录，不覆盖旧实验。
- 新条件只控制开仓，不能因活动不足、信号转弱或缺特征而阻止已有仓位的必要退出。账本留存拒绝原因、未闭合仓位及资金费状态。
- 核对每个完整组合4笔订单、两腿及开平数量一致、每笔费用为实际名义金额乘0.0003、分所现金等于初始现金加逐腿净损益。资金费未知不能记作已确认零费用。
- 同时报告每日期净收益、单位单腿名义净收益、交易数、盈利数、止盈和止损数、超时退出、回撤、持仓时长、入场清算成本及理想超深度退出依赖。
- 每轮主动解释盈利与亏损：精确拆分中价基差收敛、开平盘口成本和费用；按退出原因、方向、时段和成本分组。分别列出被挡住的原盈利、原亏损与新增实际入场，避免事后归因冒充因果改善。
- 零交易、缺数据、样本不足、亏损、审计失败都如实记录；不通过降低样本要求或补造订单让候选晋级。结束后更新本页当前结论和下一步方向。
