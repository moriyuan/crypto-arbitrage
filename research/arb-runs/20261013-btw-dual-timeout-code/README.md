# BTW 两种持仓的退出期限

本轮按持仓状态设置独立期限，不使用 AS 报价。默认仍在本所买卖一之间挂单：买入价为 ask1 减 1 个本所 tick，卖出价为 bid1 加 1 个本所 tick；成交后另一所按对手一档对冲。报价必须严格位于价差内，否则拒绝。所有代码仅用于本地历史行情回放，没有交易所下单接口。

| 参数 | 默认值 | 起点与行为 |
|---|---:|---|
| `unhedged_timeout_ms` | 1000 | 从尚未对冲的 maker 成交被接收时起算。到期撤剩余挂单、停止新增对冲，按本所反向对手一档请求退出过期数量。 |
| `hedged_hold_ms` | 60000 | 从首次 hedge 成交形成配对仓位时起算。后续补成交不延长期限；到期请求关闭剩余配对仓位。 |
| `counterparty_offset_ticks` | 1 | 价差内挂单距对手一档的本所原生 tick 数。 |

这两个期限是初始研究参数，尚未优化，也不是 AS 估计出的最优持仓周期。既有报价 TTL 为 2 秒，只控制未成交委托，和上述两种持仓时间不同。配对部分保留原参考策略的提前退出条件：扣开平手续费后止盈 5bp、相对入场时反向一档净值恶化 20bp 止损、100bp 硬止损；以实际配对买入腿名义金额为基数，和未对冲部分单独记账。资金费护栏与日终退出优先于继续持有。

超时表示发出退出请求，不表示已经成交。退出仍至少等待 100ms，再使用有效盘口、未消耗的 25% 一档深度和原生数量步长；每笔成交手续费为 0.03%。配对退出使用两所可同时满足的相同币数，允许分批。分批退出须同时保证本笔及剩余数量在当前价格下满足最小金额，避免主动制造无法关闭的小额余量；若做不到就等待更多深度。原始 maker 部分成交已形成的小额仓位仍可能不满足 5 USDT 最小名义金额，数据结束后明确标为未解决，不虚构平仓。配对退出的同步成交仍是仿真假设，未模拟两所独立拒单及真实排队。

单腿与配对库存可以同时存在，两个期限分别管理。一旦单腿超时，停止该机会新增对冲；旧未到期残量按其原期限退出，退出阶段收到的迟到开仓成交直接进入退出流程。一旦配对止盈、止损或时间到期触发，也停止新增对冲并请求处理其余未对冲库存。首次 maker 成交即请求撤单，保留 100ms 撤单延迟及 1 秒成交通知宽限。

运行时复用上轮各日经过哈希验证的公开逐笔行情和同一开仓机会池，不重新选币或搜参：

```sh
/Users/mori/code/crypto/.venv/bin/python \
  /Users/mori/code/crypto/state/arb-runs/20261013-btw-dual-timeout-code/replay.py \
  --source-summary /Users/mori/code/crypto/state/arb-runs/20261012-btw-as-comparison/days/2026-10-01/replay-causal-noon/summary.json \
  --output /Users/mori/code/crypto/state/arb-runs/20261013-btw-dual-timeout/validated-days/2026-10-01 \
  --unhedged-timeout-ms 1000 --hedged-hold-ms 60000 --offset-ticks 1
```

每次运行拒绝覆盖输出，保存 `run_metadata.json`、`status.json`、`summary.json`、`events.jsonl`、`cycles.jsonl`。参数和代码哈希写入元数据；旧 AS 实验、原始行情和结果不修改。

本轮最终结果位于 `20261013-btw-dual-timeout/validated-days`。初版 `days` 及 `initial-code` 保留诊断证据；9 月回放发现初版部分退出会制造低于最小金额的余量，修复并重跑后才进行最终汇总。`independent-audit.json` 和 `funding-interval-audit.json` 给出事后独立验收，后者的结算状态优先于运行摘要中的待审计占位状态。

仍以独立开仓机会作为实验单位，各机会不共享现金、仓位或深度，可能重叠。即使各机会均已平仓，求和结果也不是连续账户的策略收益；未解决库存不能按零损益处理。资金费必须按本轮实际持仓区间重新核验，不能沿用旧 taker 组合的“无结算”结论。
