本模块用于 BTWUSDT 公开历史行情的理想吃单回放与参数研究。它没有交易所下单接口，不读取私密凭据；旧 maker/AS/双期限回放代码及结果保留。

撮合使用本地接收时刻已经可见且有效的两所对手一档。订单执行延迟为0，双腿同时全额开平。开仓量取两所相关一档显示量、每腿250USDT和各所现金可支持1倍仓位的最小值，再按10BTW步长取整，每腿至少5USDT。每所初始1000USDT，每笔手续费0.03%。每个日期、每组参数各自为连续账户，一次最多一对仓位。

理想平仓假设全额按一档价成交，不因一档深度不足或低于5USDT而分批；订单保留 `excess_depth_qty` 和 `exit_below_min` 标志。这是有意放宽的撮合假设，不代表交易所保证成交。历史盘口不扣除模拟成交的冲击。无有效盘口时不能凭空成交；档案结束仍有仓位会明确保留。每组平仓后冷却30秒，合计已实现亏损达到10USDT后停止新增。没有强平模型，行情无效期间的持仓清算净值不计入回撤标记。

参数CSV表头为 `id,entry_bps,tp_bps,sl_bps,hard_bps,hold_ms`。入场指标是 `20000*(另一所bid1−买入所ask1)/(另一所bid1+买入所ask1)` 的原始价差bp。止盈按扣四次交易费用的组合净清算值；普通止损按净清算值相对开仓时立即反向平仓净值的恶化幅度；硬止损按绝对净清算亏损。三者以实际多头开仓名义金额为基数。优先级为日终、资金费护栏、持仓期限、硬止损、普通止损、止盈；当前时点触发即可当前盘口成交，同一行情时点平仓后不重开。

复用哈希绑定的全日盘口与逐笔活动特征，重新扫描每个可交易行情时点，不使用旧固定开仓机会池。历史20日波动率前10门槛、q25活动度和有效盘口门槛保留。q25使用各日00–12时数据校准，所以12:00UTC后才开仓。原档案23:58UTC日终护栏保留。资金费独立读取 `venue,known_at_ns,next_funding_ns` CSV，仅使用当前接收时刻已知公告，未知/过期或距结算不超过本参数持仓期限加60秒时停止新增并退出；忽略档案内按旧60秒期限预计算的 `force1`。实际结算历史仅用于事后审计。

`perfect_taker.cpp` 复用已冻结 `20261012-btw-as-code/cohort_replay.cpp` 的二进制reader，支持BTWTP002/003精确整数价格和金额。CLI必需参数为 `--tape --activity --thresholds --funding-csv --policies --entry-start-ns --output`，输出目录须不存在。

本次协议与结果目录：`/Users/mori/code/crypto/state/arb-runs/20261013-btw-perfect-taker-optimization-021035Z`。`protocol.json` 在运行前固定192组候选，8月与9月用于选参；按最差日期净收益、两日合计净收益、两日回撤之和及id排序。候选必须每个日期至少10组平仓、无残仓且账本及无资金费结算核验通过。若无候选符合，不放宽约束；若所有候选最差日期亏损，则如实报告未找到跨日盈利参数。

`run_day.py` 检查原输入、代码和参数哈希，分别执行search或evaluation，拒绝覆盖输出。`freeze_selection.py` 只读取声明的两个选参日，在运行评价日前保存选定参数与证据哈希；`selection.py` 不接受额外评价日。10月只运行冻结选择和当前参数基线。三个日期此前均已研究过，所以这属于按时间分开的内部验证，不是从未见过的独立样本。

每个参数目录含 `orders.csv`、`cycles.csv`、`equity.csv`；资金费必须以独立审计结果为准。四笔订单对应一个完整组合，分所现金只变化于实际费用及平仓损益。equity CSV仅记录开仓、平仓和结束事件，最大回撤仍在每个有效行情时点计算。

聚焦验证：`python -m unittest test_perfect_taker test_selection -v`。测试证据见本目录 `test-verification.json` 及结果目录 `selection-tests.json`。测试通过不证明理想撮合可以在实盘执行，也不证明三个已知日期上的选参有效性。

每轮回放的交付都须包含盈亏原因与下一轮方向：拆分价格损益和交易费，按退出原因、方向、持仓时间、入场跨所价差、所内价差与时段分组；检查扣费前盈利而扣费后亏损的组合，以及收益对超深度理想成交的依赖。用 `attribution.py --experiment EXP` 生成可追溯归因，指出证据支持的参数方向及拟新增限制，并区分待验证假设。不要只汇报总收益或胜率；不要把事后最优限制当成已验证改进，也不要用本轮评价结果回改已冻结参数后仍称留出验证。

深审在一次源行情扫描中保存每个实际组合开平时点的完整四个一档报价。再运行 `microstructure_attribution.py --experiment EXP`，精确分解为“跨所中价基差收敛收益 − 开平两所买卖价差成本 − 四笔手续费”。中价仅用于记账归因，不作为可成交报价；必须与每组实际四单损益逐项一致，才能判断净亏究竟来自基差方向不利还是回归幅度不足以覆盖成本。
